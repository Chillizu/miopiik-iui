# IUI 表达验收

同一组用户原题分别在 ChatGPT 和 DSH 的独立空白会话里运行，逐字保留题面与回复。题面保持自然，不指定使用 IUI、组件或操作。DSH 固定官方 DeepSeek V4.1 Flash，并记录插件版本、提示条件和会话设置。比较同一版渲染器的不同提示时，交错运行并确认双方收到的是原题。复验生成波动时另开空白会话。

## 判定

两份回复各自验收。不同构图、信息分工或互动方式都可以通过。柱状图、剖面、状态图和直接给出的文字各有适合的场合。重点是用户能否更直接地理解问题或完成任务。

- **自然、适题**。记录模型在原题下是否主动选择画面，以及画面想说明哪条关系。位置、过程、比较、权重和约束随问题选择各自的表达方式。短答和改写服从用户要求。
- **一致**。核对结论、因果、单位和题设，记录图、数值和正文的差异。影响主要解释或会使操作结果失去意义的问题计入可用性。局部误差单独记录。
- **连贯**。首屏能看懂。正文介绍问题，主图展示关系，附近的标签和读数说明发生了什么。重复的图表和无关控件会降低这一项。
- **可用**。有交互时，检查初值、一个有意义的对照或中间值及边界。操作后观察相关图元或状态，核对读数和说明。静态图和纯文按任务评估。
- **清晰**。真实窄屏与宽屏都要确认主要关系、标签、焦点与操作可见，记录横溢、局部降级和浏览器错误。

按题、按平台记录，允许保留不同的优点。先记录选择的图形及其意图，再检查浏览器里实际出现的内容。格式错误可能让有用的构图意图无法落地。事实错误、图文冲突、无效互动与渲染问题单列。图表数量、组件种数和出现率用于分析倾向。多题出现相同问题时，先归纳它们的共同原因，再选择一项能跨题改善的改动。

## 第一组原题

### 1. 空间机制

> 空杯里有枚硬币，从杯口斜着刚好看不见。眼睛和杯子都不动，倒水之后硬币怎么又出现了？

说明水面折射使光越过杯沿进入眼睛。图里眼睛、杯子、硬币的位置保持不变，光路在水面转折并能到达眼睛。

### 2. 系统负载

> 一个网站缓存命中从 95% 掉到 60%，总流量没涨，为什么后端的队伍会突然排得很长？光把缓存改回来就能马上恢复吗？

命中率变化使回源比例从 5% 到 40%。只有到达量超过处理能力才会积压。解释缓存恢复时存量仍在，有处理余量才能逐步排空。

### 3. 异步过程

> 我把一条消息发到群里，为什么对方离线时看不到，等联网后又能看到？如果我发了两条会不会乱序？

解释服务端记录、客户端离线与补收之间的关系。重试、并发和排序保证取决于实现。画面应能看到状态改变及其后果。

### 4. 并行约束

> 下午两点开始做晚餐，炖菜50分钟，能保温。只有一个烤箱，烤蔬菜25分钟，烤面包15分钟，面包出炉后放10分钟才能切；炉子和烤箱可以同时用。最早几点开饭？如果烤箱到2:10才空出来，或者拖到2:20呢？

三种情况最早开饭时间分别为 14:50、14:50、15:00。两段烤制不能重叠，面包冷却可和烤菜并行。

### 5. 一句话术语

> HTTP 304 表示什么？一句话就好。

一句话解释条件请求中的资源未修改，复用缓存副本。

### 6. 分组与权重

> 同一门课，甲班初学者18/30通过、有基础9/10；乙班初学者5/10、有基础32/40。甲班两类人各自通过率都更高，为什么总通过率反而低？如果两班的人数构成一样呢？

甲乙合计 67.5% 和 74%。用同一构成后，甲恒高 10 个百分点。若改变权重，两类的分组通过率保持不变。

### 7. 音乐结构

> C–E–G 和 E–G–C 都像 C 大三和弦，但底下的支撑好像不一样。把最低音依次换成 E 和 G，具体什么变了？只要还是这三个音，都算 C 大三和弦吗？

根音始终为 C，三个最低音依次为 C、E、G，分别为原位、第一和第二转位。位置或音位图要能解释支点变化。

### 8. 语气改写

> 请帮我把这条消息写得自然一点，直接给我改好的话：‘我已经等了半小时，你一直没回，我今天先走了。明天再聊。’ 我不想要质问的语气，也别显得在道歉。

一条可直接发送的文字，保留等了半小时、没联系上、今天先走、明天再聊。

## 跨题发现

在 `4ddadab` 的同一渲染器上，对现版和通用引导候选各跑了八题。两边简短术语与改写都保留了纯文字。候选缩短了离线消息的图文说明，形态随题而变的能力和画面正确性仍需验证。以下问题应按共同原因一起处理。

- **推理贯穿整份回复**。晚餐排程两版都没有正确处理可以并行的冷却。和弦候选先否认转位仍属于 C 大三和弦，随后又承认，结论不一致。验收先核对推理和题设，之后才评价视觉。
- **画面明确表达关系**。折射图的线条可以切换，但闭合的杯壁仍挡着光路。离线消息的状态切换成立，排序保证需要更准确的实现条件。呈现时核对方向、位置、时序和必要参照。
- **内容共用假设和数据**。缓存现版曲线在恢复后继续上升，正文说会逐步回落。另两次余热实验也重复计算了温度，导致曲线和旁边的即时读数不一致。应当从一个模型中推导曲线、标签和当前值。
- **组合在宿主中完整落地**。统计候选解释对了构成差异，但不完整的视图让主画面局部降级。和弦现版的图中标注因语法无效而被移除。需要检查实际用户看到的内容与控件变化。

通用引导候选暂留在实验中。这组样本未生成柱状图，继续用更广的题型观察图表是否被滥用。ChatGPT 的缓存题有逐字相同的历史回复可核对，其余七题和 ChatGPT 的实时交互仍待验证。

## 绘图复用试跑

四次 DeepSeek V4.1 Flash 请求各使用独立会话和一次模型调用，均使用原题。第一版提示仅补充 `repeat` 语法，电容屏题给出纯文字，和弦题给出三个手写对照图层。改用通用的空间关系判断，并在基础绘图说明里提供 `repeat` 后，电容屏题自行给出了透明电极网格的示意图。两份数组生成六条线，绘图无解析或校验降级。按去除换行和缩进的图元声明计算，同一组线条从逐条写的 450 字符缩至 299 字符。两次电容屏输出只用于观察，生成波动仍需复验。

流水线题同样用了 `repeat`，但只画出对照的一侧，并混淆了首件和整批的完成时间。与本组之前的排程和分组题一样，应同时核对图是否覆盖完整对照，以及正文、图例与题设是否一致。组件能渲染只说明语法和数据通过了这一层检查。

## 图文完整性与共享区间轴

在四道原题上比较了现版和一版更短的可选指引。八次调用均为官方 V4.1 Flash Off，使用独立会话和同一渲染器。短指引所用的上下文少了 428 token。两版都遵守了 HTTP 304 的一句话要求。两版的晚餐题都漏了可重叠的面包冷却，折射图都让会进入眼睛的光穿过杯壁。流水线题的短指引版画出了两种方式，图的时间标记和降级摘要仍有错。此候选指引留在试验中。另跑一次晚餐题的 Low 档，5,000 输出 token 全部用在推理上，未取得可验收回答。

两份排程、流水线图的共同问题是时间、描点坐标和图中数值由模型分别填写。`chart kind="interval"` 由一份起止值画出共用横轴、区间位置和点选读数，重叠区间自动分行。加上语法示例后，Flash 在延音踏板原题里选用了区间图，但填了空标签，且数据与正文相冲突。另一份流水线回答沿用了手绘。当前真实 DSH 宿主的区间对照和交互验证使用手写数据，生成质量继续按原题验收。

## 绘图位置复用

一个位置可同时作为路径端点、圆心和标签的参照点。隔离 DSH 的手写折射图共用硬币和眼睛坐标，干杯的光线停在杯壁，装水后的光线从杯沿上方经过。剪切示例在滑块更新后同步移动折线顶点、标记和标签，画幅保持一致。

以官方 V4.1 Flash Off 各跑一次折射原题和剪切题。两条回复都用了 `from`/`to`。折射回复零语法降级，入射到眼睛的线段端点也对齐了标记，但出水后仍在低于杯沿的位置穿过杯壁。剪切回复在静态路径语法内插入了算式，图元被局部降级，面积读数与正文也不同。标记实际相接、路径在物理上成立以及正文与数值一致，仍分别验收。

## 视觉选型与原始回复复验

触屏、流水线、离线补收和一句话短答，各在现行和缩短的可选提示下用官方 V4.1 Flash Off 跑一次。现行引导在三个可视题上都主动选了场景，分别用电极网格、时间区间和补收路径。短引导少用约 423 个上下文 token，流水线图有完整结构，触屏和离线补收改用纯文字。两版都按要求用一句话回答 304。短引导留在试验中。

用原始回复回放验证宿主。离线补收图合法的状态配色现在可保留，切换联网时链路与接收方描边同步更新。流水线图用数据把轴补到第 6 分钟，五段原始区间完整可见。触屏回复把控件绑到了只读派生值，基础约定已明确可写输入与只读结果的区别。下一次模型请求会使用这条约定。

## 过程播放

官方 V4.1 Flash Off 收到一道只问摆钟速度与能量如何变化的原题，主动生成了可播放的摆锤和能量图。播放和拖动共用一个时间状态。原回复里，部分读数把算式直接放入 `metric.value`，而两个派生值调用了表达式中尚未支持的 `sqrt`。回复的速度公式也与最低点最快的结论冲突。生成验收分别核对播放是否承载了过程、读数能否求值，以及各时刻是否符合正文。

## 可选指引中的结果核对

保持基础提示、渲染器和官方 V4.1 Flash Off 不变。第一版候选用通用的选图、共享数据和边界核对替换了针对故障恢复的叙述。第二版要求先给可复查的依据，再选画面，并减少重复控件。两版分别跑了四次和三次，每题使用独立会话。

- 第一版在三道可视题里分别选择了空间切换图和两份区间图，304 保持一句话。踏板题认对了会重叠的两个音，图上的结束时刻和正文仍不一致。折射图的声明通过校验，两种状态的光路却用了同一组坐标。晚餐题仍漏算并行机会，另因视图缺少绑定值而局部降级。
- 第二版的晚餐题尝试先烤面包，最终结论仍与正文里的 14:50 下限矛盾。折射题只用正文，给出了正确的出水偏折方向。踏板题的区间数据写出了 2–3 秒的重叠，正文却把重叠起点写成 1.4 秒。区间轴还因使用绘图专用颜色 `muted` 而降级。

两版保存在实验记录中。这些样本表明规则能引导画面选择，推理和图文一致性仍需要具体可核查的值。代码验收应继续把有效声明的渲染、声明本身是否合法、画面表达的结论是否正确分别记录。后续提示对照可以集中在价值最高的跨题问题，例如让图和正文共用一组已经算清的时间或位置，以及用例子展示受限表达式的适用范围。

## 读数算式与契约说明

保持可选视觉指引不变，试跑了更具体的基础语法说明和杠杆示例。两版都在 CSS 裁切原题下主动放入对照图。候选减少了重复控件，画面却把留白的方向画反。候选在踏板原题用 Markdown 表算出了 2–3 秒的重叠，在摆钟原题用支持的函数生成了阶段图和曲线，部分曲线值仍和标签矛盾。杠杆示例留作实验，基础约定明确了区间色调和读数字段的写法。

候选摆钟把总能量写成 `metric.value="$state.ke + $state.pe"`，旧版直接显示算式。缓存命中率和延音踏板样例也出现过相同写法。现在指标和进度读数可以使用引用 `$state` 的现有纯表达式，沿用求值预算和不可用提示。跨组件共用的计算仍可放在 `derive`。正文和单位的解释按原文显示。

## 图形与说明共用选择

两次官方 V4.1 Flash Off 请求分别使用 CSS 裁切原题和新的电容屏原题，题面只问现象。两份回复都主动用一个绘图选择器联动图形和外部读数，声明零降级。CSS 图仍把示意缩放比例和正文给出的比例分开计算，结果不一致。电容屏稿用同一组电极对照手指、手套和水，并把扰动与电极数标成示意。

宿主保留同一画幅和共用图元。绑定绘图和完整视图共用选择逻辑，点击图旁选项可同步读数，外部本地操作也可更新当前图层。新增的影长示例用同一个光线端点来画影子和计算影长。

## 自适应图文布局

回放同一份官方 Flash 电容屏回复，比较旧版与收紧画幅后的实屏位置。图元到图注的距离在 420 像素深色界面由 90.2 降到 20.4 像素，在 2560 像素浅色界面由 157.0 降到 31.4 像素。绘图的显示宽度与图元占用范围一致，三个状态依然共用画幅。两个读数在图注下方并排，切换后的示意值与旧版一致。

## 当前自然题的表达与同题记录

在隔离 profile 里用官方 V4.1 Flash Off 各跑一次缓存、离线补收、两班通过率和 304 原题。前三题主动选择绘图，三份声明均通过校验，短答保持一句话。缓存图的命中率滑杆联动回源值，队列由未被操作的时间状态驱动。离线图联网时同时画了共用与专属标注，发生重叠。两班通过率正文算对了各自总体率与等权结果，显示层却重新使用了错误的分母。供图和正文复用的数据、以及状态如何影响主画面，是这批题的主要缺口。

缓存原题与 ChatGPT 的独立单轮归档逐字一致。归档描述了回源倍率、后端容量、峰值积压、排空耗时和过载反馈。DSH 的入门流向图可读，缓存恢复的过程仍主要靠正文。ChatGPT 动态控件的实际画面和值无法从归档恢复，本次只完成文字和可见结构对照。

## 平面几何计算

平方根、平面长度、角度和圆周率共用现有受限表达式引擎。早前摆钟原稿里的两处 `sqrt` 现在可以求值，两项 AST 降级消失。原稿对速度随摆动位置变化的公式仍与其文字结论矛盾，属于内容核对问题。

## 情景公式共用

缓存原稿在两个情景内声明同名公式。旧版降级四项，新版在 420px 和 2560px 的隔离 DSH 宿主完整渲染，切换时命中率由 95% 变为 60%，回源速率由约 50 变为 400。原稿的等待时间公式和单位仍需推理核对。独立试件验证了图形、柱值与图外读数随同一选择更新，选择重置后恢复初值。

另用 V4.1 Flash Off 跑一次电阻原题。模型主动用绑定视图呈现两个电路，共用外层公式。图示的串联和并联读数通过核对，正文首句把串联电流写成 3 A，随后才写出正确的 1 A。

## 用题设核对图文

保持基础约定和模型档位一致。比较现行指引、用具体情形反查图文、让正文先给依据再让图复用。晚餐、硬币、踏板和 304 使用原题，另用一题缓存有效期与淘汰观察迁移。总计 14 次 V4.1 Flash Off 调用，每题每个条件单次取样。

两版候选都认对了踏板重叠的音。反查版的区间图多画了第一个音的时长，也用了区间图不支持的绑定。依据先行版的区间和替代文字对应 2–3 秒，零语法降级。两版晚餐都没给出三个正确的最早时刻，折射也仍有错误。折射的依据先行版能完整渲染，光线依然穿过杯壁。三版均保留 304 的一句话短答。

依据先行版通过替换原有说明，每道题增加 2 个上下文 token。反查版增加 102 个。两个候选留在实验中。逐题核对题设、图文、DSL 和宿主呈现，延迟本轮未测。

## 多种画面共用时间轴
