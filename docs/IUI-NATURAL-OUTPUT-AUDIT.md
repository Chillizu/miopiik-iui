# MiOpIIk · 自然 IUI 输出与回归审计（2026-11-12）

> 本文记录开发期的可复现审计数据，关联基线见 [IUI-V1-RELEASE-CANDIDATE.md](IUI-V1-RELEASE-CANDIDATE.md)。审计仅对两条授权会话做只读分析，不向仓库复制用户对话原文或身份信息。

## 审计背景

模型输出 IUI 的目标方式是在普通 Markdown 回复中直接写出受控 `iui` 围栏与行内 token，无需调用工具、检索渲染器源码或探测 DSH 服务。本次审计对比了两条真实会话，定位模型知识与运行时协议之间的差异。

## 两条真实会话的观测对比

| 观测维度 | 会话 A：自然写出画廊 | 会话 B：显式要求新版 IUI |
|---|---|---|
| 模型工具调用数 | **0** | **32** |
| IUI fenced 块数量 | 3 | 3 |
| 基线解析与校验结果 | 第一块 2 处 AST 降级；第二块因嵌套深度 4 整段回退；第三块 1 处 AST 降级 | 三块均零降级 |
| 触发降级或耗时的原因 | 使用了 `tone=accent`、`#anchor`、`chart data`、纯数字点列、`unit=$state.*` 及 4 层嵌套布局 | 为确认语法而额外读取源码、配置与服务状态 |
| 安全与体验影响 | 无任意 JS/CSS 执行，但出现局部降级与空图表 | 额外工具调用增加了响应耗时与 token 消耗 |

两条会话的 DSH 请求头均包含 **99 个工具定义（其中 14 个为 `ink_*` 工具）**；14 个 `ink_*` 工具的序列化描述与参数约 **12,328 字符**，全部工具定义约 **78,452 字符**（实际 token 开销还受宿主请求组装、前缀缓存与分词器影响）。

由于两条会话在输入内容、模型努力度（effort）、缓存命中与工具调用路径上存在差异，上述样本主要用于定位协议兼容缺口，尚不足以单独量化提示词精简带来的耗时降幅；定量结论需在同一模型、同一任务与相同努力度下通过对照实验测得。

## 工程改进项

1. **注入精简输出约定**：在 `index.js` 中注入简短的渲染契约——默认优先使用普通 Markdown，仅在数据对比、趋势或本地视图切换更清晰时输出行内 token 或 `iui` 围栏；不为画界面查找源码、探测服务或调用工具。
2. **解析与校验容错归一**：将 `chart` 的 `type/data` 归一为 `kind/series`，支持纯数字点列自动映射索引标签，加入 `accent` 语义色与 `#anchor` 页内链接支持，并将树深度预算调整为 6 以覆盖常见卡片嵌套。
3. **扩展属性状态绑定**：支持 `metric.unit`、数值与 `delta` 走相同的 `$state.*` 路径绑定；图表无有效点列时展示明确提示文案。
4. **块级组件全宽排版**：在混排 flex 容器中为块级 IUI 组件设置 `flex-basis: 100%` 独占一行，解决块级卡片与前文行内徽章同处一行时被压窄的问题。
5. **安全限制与历史兼容**：拦截原型污染属性名（`__proto__`、`constructor`、`prototype`）、非法绑定路径、非白名单链接协议与超限载荷；历史 `ink-view` 数据通过只读 legacy adapter 兼容回放。

## 已知边界与后续评估计划

- 聊天内联渲染当前仍基于本地 `dsh-client-ui-chat` 实验性补丁与浏览器开关；跨行内 token 的加粗/斜体、选中复制、屏幕阅读器朗读顺序以及流式未闭合围栏的限制依然存在。
- 保持 system prompt 片段简短，避免因枚举过多组件细节而挤占上下文。
- 后续模型基准测试将覆盖「无关 UI 的普通问答」「数据对比」「可交互趋势」三类任务，对比工具调用次数、输入/输出 token、AST 合法率、非预期降级率、总耗时与回答质量。
- 每次变更均需通过离线单测、`node tools/fork-chat-embeds.mjs --check` 与隔离浏览器 E2E 回放验证。
