# IUI 如何融入对话

模型可以在同一条 Markdown 回复里直接放一枚行内徽标或一个 `iui` 块。文字负责结论和上下文，界面负责读者需要比较、调节或展开的信息。简单问题可以只用一句话回答。交互片段用 `state` 声明参数、用 `derive` 计算结果，再让图、数据和文字绑定同一份值。读者调节参数时，浏览器在本地重算。

新块可以用 `<ui density="auto">`，由渲染器根据内容选择排版。`weight="primary"` 可以点明一个需要先读的结果。主题、换行和间距由宿主处理。有必要明确视觉密度时，也可以指定 `inline`、`compact` 或 `panel`。贴在句子里的短状态直接用 `{{badge:success:通过}}`。

从 `0.2.0-rc.3` 起，自动密度依据结构选择间距，外层沿正文展开。短操作按内容宽度聚拢，宽屏可并排显示图形，窄屏按原顺序换行。自动布局仍保留明确声明的卡片。历史声明省略 `density` 时沿用面板样式，显式密度保留原有边框策略。

## RC4 普通问题验收

继续使用 RC3 的三条问题，新增筷子从水面看起来折断的题。四条题面均无图形、组件或布局指令。RC4 共运行两轮，每题各用一个新的 DSH Headless 会话，统一使用 DeepSeek 官方 V4.1 Flash，关闭思考、工具和重试。新增题也用 RC3 跑了一次基线。

- 两轮电容屏回答都主动给出可切换的剖面。切换覆盖层会改变图形和图注。图形表达定性关系，实际触控灵敏度还受覆盖层厚度和介电性质等参数影响。[Microchip 触控覆盖层说明](https://onlinedocs.microchip.com/oxy/GUID-A8A0085D-58D1-4E41-A07D-B93BFDE11AFE-en-US-4/GUID-A6AB7775-0BF6-4B90-9886-2AB77BF61380.html)
- 解码题首轮给出可切换的注意力和候选概率示意，第二轮给出静态流程图。两种图都使用教学数据。
- 筷子题两轮都给出图层。首轮正文把水下虚像的深度方向写反。第二轮文字方向正确，图中的光线还不足以严谨说明虚像，并出现一个未联动的滑块。[OpenStax 平面界面折射图](https://openstax.org/books/university-physics-volume-3/pages/2-3-images-formed-by-refraction)
- 两轮 JavaScript 短问都用一句 Markdown。

选图、状态联动和原理准确性各有独立验收项。

## RC3 日常问法对照

三道题分别问钢化膜与手套如何影响触摸、大模型怎样选下一个词，以及用一句话区分 `??` 和 `||`。用户消息里没有界面、布局、组件或语法提示。RC2 基线两轮和三种候选指引都经由 DSH Headless 使用同一个 DeepSeek 官方 V4.1 Flash 模型。每条在新会话只发一次请求，关闭思考和工具。原始回复用于宿主回放。

| 问题 | RC2 两次 | RC3 采用的指引 |
| --- | --- | --- |
| 钢化膜与手套 | 纯 Markdown，包括长表格或文字解释 | 自发生成试算，滑块与开关影响示意读数。附带图表的动态值写法有误。 |
| 下一个词 | 均自发生成交互。一个是上下文切换表，一个是温度与最高概率试算，附带图表无效。 | 更早插入温度实验，派生公式和图表写法有误。 |
| 一句话区分运算符 | 均用一句 Markdown | 一句 Markdown |

第一版候选能生成触屏定性试算，解码题保持纯文字。另一次尝试加入绑定数据的折线图范例，模型主动选择了触屏剖面与候选词图，但多个绑定无效，短答也插入了交互。因此采用上表中的指引。此样本用于定位触发、摆放和有效性问题，样本量不足以估计触发率或稳定性变化。

## 可回放示例

以下是本次为验证渲染能力编写的三条完整回复。前后文字可以连续阅读，界面在合适的位置补充信息。

| 普通问题 | 示例与预期行为 |
| --- | --- |
| 300 次请求里，缓存命中率从 60% 提高到 80%，会少多少回源？调到 90% 呢？ | [缓存试算](../test/fixtures/natural/cache-explorer.md)。行内徽标标注样本范围，滑杆从 80% 调到 90% 时，主指标从 60 次变成 30 次。计算口径可展开。 |
| API 最近五天的平均延迟是 120、145、180、160、210 毫秒，怎么判断趋势和排查？ | [延迟趋势](../test/fixtures/natural/api-trend.md)。一幅折线图接在判断之后，随后用 Markdown 表格列出排查方法。 |
| 有 180 个文件待转码，每个约 6 分钟。4 个工作槽在 2 到 4 小时内能做多少？ | [转码窗口](../test/fixtures/natural/transcode-window.md)。切换窗口和工作槽同时更新进度、剩余量和任务流，积压状态随结果变化。 |

JavaScript 里的 `??` 只在左值为 `null` 或 `undefined` 时取右值，`||` 对 `0`、`false`、空字符串等假值也会取右值。这样的问题用一句 Markdown 即可。

## DeepSeek 官方八题对照

两组都由 DSH 0.2.2-rc.1 Headless 在独立会话中发起。均使用 `deepseek-official/deepseek-flash`（DeepSeek-V4.1-Flash），关闭思考、工具和重试。每题只发原始用户问题，插件在原生系统提示中注入该组的完整契约。对 0.1.1 和最终候选的全部 16 条回复，逐条核对了系统提示、模型路由、模型请求数和提供方用量。

| 指标 | 0.1.1 | 0.2.0-rc.1 |
| --- | ---: | ---: |
| 声明约定字符数 | 3,944 | 1,881 |
| 使用 IUI 块的回答 | 5/8 | 6/8 |
| 每条回复中 IUI 块正文占比的均值 | 36.05% | 30.84% |
| IUI 块数 | 5 | 10 |
| 使用可写控件的回答 | 1/8 | 2/8 |
| 整块解析失败／局部节点降级 | 0／1 | 0／0 |
| 提供方输出 token 合计 | 4,649 | 6,147 |
| Headless 单题耗时中位数（含启动和输出） | 6.82 秒 | 8.18 秒 |

其中一句话问题两组都用原生 Markdown。最终候选在缓存题中自行生成了带局部派生的滑杆。两次中间迭代分别发现重复呈现和控件未接到结果的问题。候选把真实样本中的步骤正文和 `label`／`desc` 归一到已有 `title`／`note`。这些输出复算时保留原文。

最终样本沿用了声明式密度，但八条都未选择句内 token，并且有些回复仍出现信息重复。延迟排查题中模型给出的文字例值 180 ms 与其声明式公式的渲染值 156 ms 不一致。当前结果支持按需混排、生成和执行本地试算，仍需扩大重复采样才能估计模型选择的稳定性或输出成本。

## 真实 DSH 宿主回放

在独立 DSH Web profile 中用 Chromium 验证 1280、420、360 px 和 420 px 深色主题。固定样本覆盖 Markdown 正文与句内徽标、三档密度、键盘操作、剪贴板预览和写入、条件图形，以及代码围栏中的示例保留。后续块流式到达时，前一块的 DOM 和已有控件状态持续有效。官方模型的三条原始回复也在 1280 px 浅色和 420 px 深色中原样回放，分别呈现 3、0、1 个 IUI 块，零浏览器错误、零横向溢出。缓存题滑杆从 60 改到 200 ms，两个派生耗时从 7.2／3.6 秒变为 24／12 秒，回源次数降幅保持 50%。

## 八题历史对照

已对照本机 DSH 归档日志核验 16 份 DeepSeek Flash 子代理答复。两组共用同一套日常题目，系统提示均包含完整的 0.1.1 契约。实验角色用工具读取额外材料，基线组再次读取 0.1.1 契约，第三轮组则读取实验契约。因此这批数据衡量的是在既有系统提示下补充两份不同材料时的表现。原始题目与数据可在原实验工作树的 `.dsh/bench/round3/` 查看。

| 题目 | 再读 0.1.1 契约 | 加读第三轮实验契约 |
| --- | --- | --- |
| 幂等与重试 | Markdown + 无围栏判别表 | Markdown + 判别表 |
| 小团队选消息队列 | Markdown + 对照表及提示 | Markdown + 对照表 |
| 五天 API 延迟 | Markdown + 指标、趋势图和步骤 | Markdown + 指标和趋势图 |
| 新同事上手安排 | Markdown + 步骤 | Markdown + 步骤 |
| CI 偶发超时 | Markdown + 步骤及表格 | Markdown + 表格 |
| 鉴权重构计划 | Markdown + 表格 | Markdown + 步骤 |
| 一句话解释 `??` 与 `||` | Markdown | Markdown |
| 缓存命中率对后台的影响 | Markdown + 指标和表格（表格降级） | Markdown + 指标和表格 |

按插件切分器复算，两组各有 7/8 条答案包含 IUI。基线的幂等性答复用裸 `<ui>` 输出表格，也能被识别，历史围栏统计漏掉了这一块。逐条计算 IUI 块正文占比后取平均，由 46.25% 降到 32.75%。基线识别出 7 个 `panel` 和 1 处节点降级，第三轮识别出 7 个 `compact` 和零降级。两组的行内 token、动态控件和语义权重使用数均为 0。第三轮 Q3 按子代理自行编辑后的最终文本计入。

这批旧归档用于核对第三轮交接。归档中的 provider 用量包含实验工具回合，IUI 正文字符占比只衡量占用的文字篇幅。
